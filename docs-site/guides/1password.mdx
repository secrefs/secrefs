---

```bash
STRIPE_KEY=sec://1password/Engineering/Stripe#api_key
```

A reference maps directly onto a 1Password
[secret reference](https://developer.1password.com/docs/cli/secret-reference-syntax/):

| SecRefs | 1Password |
|---|---|
| `sec://1password/Engineering/Stripe#api_key` | `op://Engineering/Stripe/api_key` |
| `sec://1password/Engineering/Stripe/Live#webhook` | `op://Engineering/Stripe/Live/webhook` (section `Live`) |
| `sec://1password/Engineering/Stripe/api_key` | `op://Engineering/Stripe/api_key` |
| `sec://1password/Engineering/Stripe` | `op://Engineering/Stripe/password` |

- Vault, item and section can be names or ids. A reference can't contain
  spaces, so write a name that has one percent-encoded (`My%20Vault`), or use
  its id.
- With no field, the item's `password` is returned.
- The field is used as written. Unlike other providers, `#a.b` is a field
  named `a.b`, not a JSON path.

## Authentication

There are two ways in. Neither writes anything to disk.

### A service account (CI, servers, agents)

```bash
export OP_SERVICE_ACCOUNT_TOKEN="ops_..."
```

Non-interactive. A [service account](https://developer.1password.com/docs/service-accounts/)
sees only the vaults it has been granted, and a vault it can't see is
reported as *not found*. Service accounts are rate-limited, so SecRefs
resolves every reference requested at once, such as a whole `.env`, in a
single request.

### The desktop app (a developer's machine)

```bash
export OP_ACCOUNT="acme"   # the account name in the app's sidebar, or its id
```

Each process that resolves references asks the 1Password app for access, and
the app asks you to approve it the way you unlock the app: Touch ID, Windows
Hello, your account password or your identity provider. The app shows the
process name and path, so check it's the command you ran. Access lasts until
ten minutes of inactivity, or until you lock the app.

First, turn on the app's option to integrate with the 1Password SDKs. Your
password never passes through SecRefs.

If both variables are set, the service account is used.

## In secrefs.config.json

```json
{
  "providers": {
    "op-ci": { "type": "1password", "tokenEnv": "OP_TOKEN_CI" },
    "op":    { "type": "1password", "account": "acme" }
  }
}
```

An alias with `account` and no `tokenEnv` always uses the desktop app, even
if a token is present in the environment.

## Installing

Node: included in `@secrefs/node`. The SDK is loaded only when a
`sec://1password/...` reference is resolved.

Python: `pip install 'secrefs[1password]'`. The SDK ships prebuilt native
wheels for macOS, Linux and Windows on x86-64 and ARM64.

<Warning>
  An expired desktop session or a revoked token is reported once as an
  authentication failure, never as missing secrets. Hitting a rate limit is
  reported as transient.
</Warning>
